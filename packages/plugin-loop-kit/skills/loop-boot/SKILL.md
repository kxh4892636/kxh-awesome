# Loop Boot

用户提供一组 skill 并将其编排成一个新的开发流程 skill。生成的新 skill 使用 `ASK_MATT_TEMPLATE.md` 的组织方式，特别是「## The main flow: idea → ship」部分。

## 步骤

1. **收集输入**
   - 记录用户提供的 skill 名称、路径、用途说明和想生成的新 skill 名称（默认为 `loop-dev`）。
   - 如果某个 skill 可以从当前工作区定位，直接读取它；如果无法定位，只问一个阻塞问题。

2. **读取 skill**
   - 完整阅读每个输入 skill 的 `SKILL.md` 及其路由的引用文件。
   - 提取每个 skill 的触发条件、核心步骤、分支和限制。

3. **用 grilling 对齐需求**
   - 用 `grilling` 的方式逐个问题确认需求。
   - 必须用户确认：
     - 开发流程选择 TDD/BDD 还是瀑布；
     - **编排流程应该有那些分支**：流入某个阶段是否需要路由到不同逻辑；
       - 例如「讨论」阶段结束后决定是否创建分支生成技术/需求文档还是直接进入下一阶段；
       - 例如影响面单一、验收路径明确的需求在「计划」结束后可以直接进入下一阶段；
       - 例如跨模块、多会话开发、验收链路复杂的的需求在「计划」结束后需要进行计划的存储/拆分/多会话状态同步。

4. **选择开发流程**
   - 默认优先选择 TDD/BDD：`需求 -> 讨论 -> 计划 -> 测试 -> 开发 -> 验收`。
   - 当任务主要是低风险、顺序明确、测试只能在实现后有效确认时，选择瀑布：`需求 -> 讨论 -> 计划 -> 开发 -> 测试 -> 验收`。
   - 如果使用 TDD/BDD，前端推荐 BDD，后端推荐 TDD。
   - **必须用户明确指定开发流程**，并基于事实提供选择建议，遵循用户指定。

5. **编排 skill**
   - 为开发流程的每个阶段指定应调用的 skill、调用顺序和分支条件。
   - 将跨阶段通用的 skill 放入“底层参考”，不要在多个阶段重复解释同一含义。
   - 将不总是进入开发流程的 skill 放入“独立入口”或“分支”。

6. **生成新 skill**
   - 调用 `writing-great-skills`，基于 `ASK_MATT_TEMPLATE.md` 创建 skill。
   - 新 skill 的“讨论”阶段必须要求使用 `grilling` 与用户对齐需求。
   - 新 skill 仅用于编排和路由 skill，不需要暴露 skill 的内部实现。

## 上下文约束

- 需求、讨论、计划必须留在同一个上下文中完成，避免丢失用户约束。
- 如果生成的新 skill 会驱动多轮、多 issue 或多会话开发，必须在新 skill 中写清楚如何拆分会话并管理上下文。
- 测试/验收相关 skill 会在「计划」「测试」「验收」多个阶段调用；
