# ETF 前端测试代码化

ETF 前端的消费者回归从 agent 驱动的 Markdown 验收文档（`market-dashboard/e2e/index.md`）转为代码驱动的三层测试：单测（Vitest node 环境，覆盖纯数据逻辑）、组件测试（Vitest browser mode，真实 Chrome，canvas 渲染与 tooltip/缩放/拖拽交互在此层回归，API 数据在 Connect transport seam 上 mock）、薄 E2E（Playwright，只保留默认行情、核心交互联通、窄屏、停服恢复四条消费者旅程）。选择代码化是因为 Markdown 验收依赖 agent 每次手工驱动浏览器，结果不可复跑、证据随会话蒸发，而代码测试可通过 `test` script 接入仓库根 `ready` 门禁；代价是引入 Vitest/Playwright 依赖与 E2E 进程编排（Playwright global setup 管理 etf-service 生命周期）的维护成本，且停服场景要求后端由 Playwright 自己拉起，后端为外部管理时该场景跳过。这是 ETF 前端的领域例外：`/acceptance` 的 Markdown 验收形态对仓库其他领域继续有效。
