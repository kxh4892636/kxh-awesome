# 后端不可用提示

## 目标

验证后端服务不可用时，前端通过真实 Chrome 页面展示可理解的错误提示，而不是白屏、静默失败或控件卡死；后端恢复后，刷新页面可以恢复正常看板。

## 执行方式

- 使用 `@浏览器`（Browser 插件）控制真实浏览器页面执行；历史文档中的 `@chrome` 也指同一类真实浏览器执行方式。
- 不使用 Playwright CLI，不写前端单元测试或组件测试。
- 不通过修改前端代码制造错误；通过临时停止或隔离 `etf-service` 验证真实失败路径。
- 执行结束必须恢复后端服务。
- 由于 React Query 会重试请求，后端停止后错误提示不会立即出现；实测需要等待约 `10` 秒以上。
- 如果使用默认 React Query 重试策略，错误提示可能需要等待 `30` 秒以上才稳定出现；测试时建议等待到 `35` 秒后再判定错误提示缺失。
- 如果服务停止期间 Chrome 进入 `ERR_CONNECTION_REFUSED` 内置错误页，恢复服务后优先打开一个干净的新标签页或重新导航到 `http://localhost:5173`，不要继续在内置错误页上做应用断言。
- 后端不可用期间，页面可能先显示空数据态 `当前筛选下没有可展示的数据`，随后再出现服务不可用错误提示。
- 控制台会记录预期的 `Failed to fetch` 网络错误；恢复后不要用历史 console error 总数判断失败，应确认页面恢复且不再出现新的失败态。
- 页面上的行情数值、数据范围日期和数据行数不是固定值，恢复验证只校验存在且格式正确。

## 前置条件

- `etf-dashboard` 已启动并监听 `http://localhost:5173`。
- 该链路会临时停止或隔离 `etf-service`，建议在独立测试时段执行。
- 停止进程前先确认 `8080` 端口对应进程确实是 `etf-service`。

## 操作步骤

1. 确认当前正常链路可用：打开 `http://localhost:5173`，等待浏览器标题为 `ETF Dashboard`，页面显示默认标的和 K 线图。
2. 定位 `8080` 端口监听进程，并确认命令行属于 `apps/etf-service` 或 `tsx watch src/main.ts`。
3. 停止 `etf-service`，或临时让前端 API 指向不可用地址。
4. 在同一个 Chrome 标签页刷新 `http://localhost:5173`。
5. 等待证券列表或日线数据请求失败。
6. 至少等待 `10` 秒，覆盖请求重试延迟。
7. 观察页面错误提示和应用外壳。
8. 检查控制台错误，记录是否为预期的网络失败。
9. 恢复 `etf-service`。
10. 再次刷新 `http://localhost:5173`。
11. 等待默认标的、摘要区和 K 线图恢复。
12. 确认页面不再显示后端不可用错误提示；如需检查控制台，只检查恢复后是否继续新增失败日志。

## 验收断言

后端不可用时：

- 浏览器标题仍为 `ETF Dashboard`。
- 页面仍显示应用外壳和 `ETF K 线看板`。
- 页面显示错误提示 `数据加载失败，请确认 etf-service 已启动`。
- 在错误提示出现前，短暂显示空数据态是可接受的重试中间态。
- 页面不白屏。
- 控件不会永久处于不可恢复的 loading 状态。
- 控制台错误只反映预期网络失败，不出现 React 渲染崩溃。

后端恢复后：

- 刷新页面后默认标的恢复为 `红利低波100 · 930955.CSI`。
- 摘要区恢复显示 `最新收盘`、`涨跌幅`、`成交额`、`数据范围`。
- 最新收盘和成交额显示有效数字，涨跌幅显示有效百分比。
- 数据范围匹配 `YYYY-MM-DD 至 YYYY-MM-DD`。
- K 线卡片右上角恢复显示 `cache · 正整数 条` 或 `refreshed · 正整数 条`。
- Chrome 截图中 K 线图不是空白。
- 页面不再显示后端不可用错误提示。
- 控制台历史中可能仍保留停服期间的 `Failed to fetch`；恢复验收以页面状态和是否继续新增失败日志为准。

## 失败定位

- 后端不可用时白屏：检查 React Query 错误态和页面错误兜底渲染。
- 错误提示不出现：检查 `securitiesQuery.isError` 和 `dailyBarsQuery.isError`。
- 控件一直 loading：检查请求失败后的 loading/fetching 状态是否正确结束。
- 后端恢复后仍失败：检查服务端端口、前端 API 地址和浏览器缓存。
- 停止了错误进程：恢复被误停的服务，再重新确认 `8080` 端口监听进程。
