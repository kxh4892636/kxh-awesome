# skill-cleanup

清理 skill 时，目标是移除沉积内容，同时保留仍能改变执行行为的规则。不要只按关键词删除；先证明引用是否仍然有效，再改文件。

## 流程

1. **确定范围**

   找到用户指定的 skill、插件或目录。若用户没有指定范围，优先检查当前插件或当前仓库中与请求相关的 skill 目录。

2. **建立事实清单**

   读取目标目录的实际结构：
   - 当前存在的 skill 文件夹和 `SKILL.md`
   - `agents/openai.yaml`、manifest、update registry、AGENTS.md 等入口文件
   - 目标 skill 正文中提到的 skill 名、插件名、相对路径、绝对路径、URL、脚本、命令和工具名

   用实际文件系统和当前工具列表校验引用。对 URL，只有在任务要求清理 URL 或该链接影响执行时才联网验证；否则标记为外部引用，避免把未验证链接当作坏链。

3. **分类引用**

   把每条可疑引用归入一个状态：
   - `live`：目标存在，且当前流程仍需要它。
   - `renamed`：旧名不存在，但能从当前目录、manifest、registry 或上下文确定新名。
   - `dead`：目标不存在，且没有可证明的新目标。
   - `external`：目标在当前目录外，例如其它插件、远程 URL、系统工具或用户环境。
   - `uncertain`：无法从现有上下文证明有效或无效。

4. **处理规则**
   - 删除 `dead` 引用，以及围绕它产生的解释性句子、兼容说明、迁移叙述和旧流程步骤。
   - 将 `renamed` 引用替换为当前名称，但不要保留“旧 X 已由 Y 替代”这类历史说明，除非 update registry 需要记录同步 overlay。
   - 保留 `live` 引用。
   - 保留必要的 `external` 引用，但避免跨插件分流说明，除非目标 skill 的职责就是跨插件路由。
   - 对 `uncertain` 引用先报告，不要静默删除。
   - 删除重复解释和无行为差异的句子；保留可执行步骤、验收标准、边界条件和验证方式。

5. **编辑**

   最小化修改面。优先清理目标 skill 本身；只有入口文件、manifest、registry 或 AGENTS.md 明确引用了过期对象时才同步更新它们。

6. **验证**

   至少完成以下检查：
   - 用 `rg` 确认已删除或已改名对象不再残留在目标范围内。
   - 校验 `SKILL.md` frontmatter 只有当前运行环境接受的字段。
   - 若目标属于插件，运行插件验证；若只有单个 skill，运行 skill validator。
   - 运行 `git diff --check` 检查空白和换行问题。

## 输出

交付时说明：

- 删除或替换了哪些失效引用。
- 哪些引用被确认仍有效。
- 哪些引用因证据不足而保留或需要用户确认。
- 已运行的验证命令和结果。
