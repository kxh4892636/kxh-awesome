# 加载、刷新与缓存

## 目标

验证用户用真实 Chrome 打开 ETF 看板后，可以完成证券列表加载、默认标的选择、日线数据加载、摘要展示和 K 线渲染；点击刷新后页面保持可用，并按后端缓存语义返回 `cache` 或 `refreshed` 状态。

## 执行方式

- 使用 `@chrome` 插件控制真实 Chrome 页面执行。
- 不使用 Playwright CLI，不写前端单元测试或组件测试。
- 前端地址使用 `http://localhost:5173`，后端地址使用 `http://localhost:8080`。
- 页面是否打开成功优先用浏览器标题判断：`document.title === "ETF Dashboard"`。
- 图表渲染以真实 Chrome 截图和可见页面为准；不依赖注入 `window.fetch`、`performance` 或 canvas 像素直读。
- 网络请求证据优先通过页面状态、后端终端日志和 K 线卡片右上角缓存状态判断。
- 页面上的行情数值、数据范围日期和数据行数不是固定值，只校验存在且格式正确。
- 摘要区数值只要求是有效数字或百分比；K 线卡片右上角只要求匹配 `cache|refreshed · 正整数 条`。
- 刷新请求可能很快完成，测试时不要依赖肉眼捕捉按钮 loading；点击后等待 K 线卡片右上角缓存状态重新稳定显示。
- 刷新前后可以记录两个分段控件的选中值，正常情况下应保持为 `日` 和 `全部`。

## 前置条件

- `etf-service` 已启动并监听 `http://localhost:8080`。
- `etf-dashboard` 已启动并监听 `http://localhost:5173`。
- 后端已用 `apps/etf-service/data/*.json` 完成初始化入库。
- 当前初始化数据包含 `红利低波100 · 930955.CSI` 和 `中证红利质量 · 932315.CSI`。
- 两个标的都应有数据范围和正整数行数，但具体日期、行数和行情数值会随初始化数据变化，不作为固定断言。

## 操作步骤

1. 用 `@chrome` 打开 `http://localhost:5173`。
2. 等待页面 load 完成，并确认浏览器标题为 `ETF Dashboard`。
3. 等待页面可见 `ETF K 线看板`。
4. 确认默认标的显示为 `红利低波100 · 930955.CSI`。
5. 检查摘要区显示 `最新收盘`、`涨跌幅`、`成交额`、`数据范围`。
6. 检查摘要区的最新收盘、涨跌幅、成交额都有数值，数据范围匹配 `YYYY-MM-DD 至 YYYY-MM-DD`。
7. 检查 K 线卡片右上角显示 `cache · 正整数 条` 或 `refreshed · 正整数 条`。
8. 通过 Chrome 截图确认 K 线图、成交量区域和 MA 图例已实际渲染，不是空白区域。
9. 检查 Chrome 控制台没有 error 级别应用错误。
10. 点击 `刷新` 按钮。
11. 等待 K 线卡片右上角重新稳定显示 `cache · 正整数 条` 或 `refreshed · 正整数 条`。
12. 确认周期和范围仍分别选中 `日`、`全部`。
13. 再次检查默认标的、摘要区、数据范围、K 线截图和控制台。
14. 如需确认刷新确实触发后端请求，查看后端终端在点击刷新时间点附近是否出现 `/api/market/getDailyBars` 访问记录。

## 验收断言

首次加载后：

- 浏览器标题为 `ETF Dashboard`。
- 页面显示 `ETF K 线看板`。
- 默认选中 `红利低波100 · 930955.CSI`。
- 摘要区显示 `最新收盘`、`涨跌幅`、`成交额`、`数据范围`。
- 最新收盘和成交额显示有效数字，涨跌幅显示有效百分比。
- 数据范围匹配 `YYYY-MM-DD 至 YYYY-MM-DD`。
- K 线卡片右上角显示 `cache · 正整数 条` 或 `refreshed · 正整数 条`。
- 页面显示 `MA5`、`MA8`、`MA13`、`MA21`、`MA34`、`MA55` 图例按钮。
- Chrome 截图中 K 线图、成交量柱和 MA 线可见。
- 页面不显示 `当前筛选下没有可展示的数据`。
- 页面不显示 `数据加载失败，请确认 etf-service 已启动`。
- 控制台无 error 级别应用错误。

点击刷新后：

- 当前选中的标的不变。
- 当前周期和范围选中态不变。
- 摘要区仍显示最新收盘、涨跌幅、成交额和数据范围。
- K 线卡片右上角显示 `cache · 正整数 条`，或在缺失缓存测试数据时显示 `refreshed · 正整数 条`。
- Chrome 截图中 K 线区域仍正常渲染。
- 页面无错误提示。
- 控制台无 error 级别应用错误。

## 缓存语义

- 数据库已覆盖有效请求区间时，后端返回 `cache`。
- 数据库缺少有效交易日数据时，后端远端拉取数据，过滤当天及未来数据，入库后返回 `refreshed`。
- 数据库最新数据为 `t-1` 的最新交易日；当天数据不入库。
- 用户请求早于 `securities.earliest_trade_date` 的日期无效，不触发远端拉取。
- 前端 e2e 不直接改数据库；需要强制验证 `refreshed` 时，应在独立后端测试环境中准备缺失缓存数据。

## 失败定位

- 页面标题不是 `ETF Dashboard`：检查前端服务是否打开了正确应用。
- 页面显示加载失败：优先检查 `etf-service` 是否在 `8080` 监听。
- 标的列表为空：检查 `/api/securities/list` 和 SQLite 初始化数据。
- K 线区域空白：检查 `/api/market/getDailyBars` 返回的 `bars` 是否非空，以及浏览器控制台错误。
- 点击刷新后状态异常：检查刷新按钮是否触发 `dailyBarsQuery.refetch()`。
- 刷新后控件状态丢失：检查 React state 是否被不必要重置。
